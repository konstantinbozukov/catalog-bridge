# Comp page methodology — Catalog Bridge

Every published comp page follows this standard. v0 uses **public specs + review consensus** — not hands-on testing unless explicitly stated.

## 1. Lead with the constraint

State who the page is for and who should skip it:

- Space (sq ft, counter footprint)
- Household size (1–2 people, dorm, etc.)
- Budget cap
- Use case (meal prep beginners, pour-over coffee, etc.)

## 2. Pick 3–5 ASINs max

Each pick includes:

- **Best for** — the specific constraint match
- **Skip if** — when another pick or no purchase is better
- Key specs from public listing (capacity, dimensions, wattage, dishwasher-safe, etc.)
- Review signal: star rating + approximate review count (dated)

No single “winner takes all” unless one product clearly dominates on the stated constraint.

## 3. Comparison table

| Product | Price band | Size / capacity | Key spec | Review signal |
|---------|------------|-----------------|----------|---------------|

Prices are **bands** or “as of [date]” — Amazon prices fluctuate.

## 4. Disclosure

Every page includes FTC affiliate disclosure: we may earn commission from qualifying purchases through our Amazon links.

## 5. Refresh rule

- `updated_at` on every page
- Re-check picks when a product is discontinued or price shifts materially
- Log changes in page frontmatter or git history

## 6. Venue posting rule

Only link this page in external venues when the question **exactly matches** the constraint. If no comp fits, skip — do not force a link.

## What we avoid

- “We tested” without actual testing
- Health, medical, or pressure-cooker safety claims
- Broad head terms without constraints
- Raw Amazon affiliate URLs in external posts
